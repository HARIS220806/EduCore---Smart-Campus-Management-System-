# Smart Campus — Backend

Express REST API for the Smart Campus Management System. Pairs with the
`frontend/` app in this repository.

## Why a JSON file instead of MongoDB?

The original scaffold pointed at a MongoDB Atlas cluster via a connection
string containing live credentials. For a prototype meant to run anywhere
with zero setup (and to avoid shipping a real database password in a repo),
this backend instead uses a tiny embedded JSON-file store
(`src/db/store.js`, data persisted to `data/db.json`). It exposes the same
kind of collection API (`find`, `insert`, `update`, `remove`) a Mongoose
model would, so swapping in real MongoDB later only means rewriting
`src/db/store.js` — no route file needs to change.

## Quick start

```bash
cd backend
npm install
cp .env.example .env      # defaults already work for local dev
npm run seed               # creates demo accounts + sample data
npm run dev                 # starts on http://localhost:5005
```

## Environment variables (`.env`)

| Variable          | Meaning                                         | Default                     |
|-------------------|--------------------------------------------------|------------------------------|
| `PORT`            | API port                                         | `5005`                       |
| `JWT_SECRET`       | Secret used to sign auth tokens                  | *(set a real one in prod)*   |
| `JWT_EXPIRES_IN`   | Token lifetime                                   | `8h`                          |
| `CLIENT_ORIGIN`    | Allowed CORS origin (the frontend's dev URL)      | `http://localhost:5173`       |

```
  routes/
    auth.js              register, login, me, change-password, forgot/reset password

    courses.js             course CRUD, enrolled-student listing
    attendance.js           mark + query attendance, per-student summary
    marks.js                  enter/query marks, CGPA-style summary
    assignments.js             create/list, student submit, faculty grade
    announcements.js            audience-scoped announcements
    timetable.js                 weekly class schedule
    notifications.js              in-app notification feed
    dashboard.js                   role-specific dashboard aggregates

    settings.js                      institution-wide settings (admin only)
  utils/
    helpers.js                        shared query/validation helpers

  db.json              Generated by the store — the "database" file
```

## Auth model

- Passwords are hashed with bcrypt (never stored in plain text).
- `POST /api/auth/login` returns `{ user, role, accessToken }` — a signed
  JWT (not a Mongo ObjectId-based mock token).
- Protected routes require `Authorization: Bearer <token>`.
- Role enforcement happens **in the backend** (`authorize('admin', ...)`),
  not just in frontend route guards — the frontend's `ProtectedRoute` /
  `RoleRoute` are UI convenience only, exactly as the frontend README warns.

can) is required.

## Notes on scope (what's intentionally simplified for a prototype)

- No file upload for assignment submissions — students submit text and/or a
  link. Swapping in real file upload (e.g. `multer` + disk/S3 storage) only
  touches `routes/assignments.js`.
- Password reset has no email server: the reset link is logged to the
  backend console, and returned directly in the API response as
  `devResetLink` whenever `NODE_ENV !== 'production'`.
- "Enrollment" is modeled simply as *same department + same year* rather
  than a many-to-many enrollment table — reasonable for a single-section
  college prototype, and easy to replace with a real `enrollments`
  collection later.
